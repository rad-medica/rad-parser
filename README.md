# rad-parser

**rad-parser** is a lightweight, performant, and self-contained DICOM parser for Node.js, Bun, Deno, and browsers, built with TypeScript and with **zero external dependencies**.

It is designed for safety, efficiency, and reliability in medical imaging applications, command-line utilities, and cloud-based pipelines where dependency bloat and performance are critical concerns.

[![npm version](https://img.shields.io/npm/v/rad-parser.svg)](https://www.npmjs.com/package/rad-parser)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)
[![TypeScript](https://img.shields.io/badge/TypeScript-5.0+-blue.svg)](https://www.typescriptlang.org/)

## Features

- ✅ **Zero Dependencies**: Pure TypeScript/JavaScript implementation.
- ✅ **Extensive Format Support**: Explicit/Implicit VR, Little/Big Endian, Deflated Explicit VR Little Endian (bundled synchronous inflater), every VR of PS3.5 including VR UN re-read through the PS3.6 dictionary.
- ✅ **Values as stored**: DA/TM/DT are returned as their text (no invented dates); parse helpers return components.
- ✅ **Lazy pixel access**: Pixel Data is returned as zero-copy views (or skipped) with the absolute offset of the value, every fragment and the Basic Offset Table.
- ✅ **Automatic Codec Loading**: Compressed images (RLE, JPEG, JPEG 2000, etc.) are decoded on-demand with no extra setup.
- ✅ **Extensible Codec System**: “Adapter” classes allow you to integrate your own decoders (e.g., from a WebAssembly library like OpenJPEG or CharLS).
- ✅ **DICOM Manipulation**: `anonymize` (PS3.15 Annex E Basic Profile, full Table E.1-1, nested sequences) and `write` (parse → write → parse keeps every value).
- ✅ **Streaming Parser**: Incremental parsing with backpressure-friendly callbacks.
- ✅ **Multiple Parse Depths**: Fast/shallow/light/full/streaming modes to match your workload.
- ✅ **Safe & Performant**: Designed for efficient binary parsing with strict bounds checking.

## Command-Line Interface (CLI)

`rad-parser` includes a powerful CLI for inspecting, transcoding, and converting DICOM files.

> **[View Full CLI Documentation](./docs/cli.md)**

### **Quick Command Summary**

| Command                               | Description                                            |
| :------------------------------------ | :----------------------------------------------------- |
| `dump <file>`                         | Parse and print all tags from a DICOM file.            |
| `transcode <in> <out> --format <fmt>` | Transcode DICOM to RLE, JPEG, JPEG-LS, J2K, or Native. |
| `image <in> <out> --frame <n>`        | Export DICOM frames to PNG or JPEG images.             |
| `help`                                | Show detailed help message.                            |

### **Examples**

**1. Dump tags:**

```bash
npx rad-parser dump "scan.dcm"
```

**2. Compress to RLE:**

```bash
npx rad-parser transcode "native.dcm" "compressed.dcm" --format rle
```

**3. Export frame to PNG:**

```bash
npx rad-parser image "scan.dcm" "output.png" --frame 0
```

## Benchmarks

976 synthetic files generated by [radspider](https://github.com/rad-medica/radspider)
(every codec, deflate, big endian, VR UN, PET, enhanced multi-frame, SR/KOS/PDF;
no patient data), all in memory, median of 15 rounds after 2 warm-up rounds
(`bun run benchmarks/synthetic_compare.ts <dir>`, Bun 1.4, one machine; compare
ratios, not absolute times):

| Parser / mode                                 | ms per round (976 files) |
| --------------------------------------------- | ------------------------ |
| dicom-parser `parseDicom` (no value decoding) | 31–41                    |
| rad-parser `shallow` (locations only)         | 34–59                    |
| rad-parser `full`, pixel views                | 50–75                    |
| rad-parser `light` (no pixel values)          | 47–81                    |
| rad-parser `full`, pixel copies               | 71–120                   |
| rad-parser 2.0.0 `full` (before)              | 145                      |

`full` decodes every value (dicom-parser decodes on access), so it is not the
same work; `shallow` is the comparable mode.

## Library Usage

### Parse Modes

- `fast` / `shallow`: element locations only (`vr`, `length`, `dataOffset`; Pixel Data `fragments` and `basicOffsetTable`).
- `light`: all values except Pixel Data (its locations are still reported).
- `full`: all values; Pixel Data as zero-copy views by default (`pixelData: "view" | "copy" | "skip"`).
- `lazy`: values decoded on first access.
- `streaming`: incremental parsing via callbacks on chunks/streams.

Explicit VR Big Endian: OW/OF/OL/OD/OV values, Pixel Data included, are returned byte-swapped to Little Endian (a copy); OB/UN are never swapped. See the [API reference](./docs/api.md#byte-order-explicit-vr-big-endian).

### **Example 1: Basic Parsing (Metadata Only)**

Use the `light` (medium) parse type to quickly read all tags without loading the bulky pixel data.

```typescript
import * as fs from "fs";
import { parse } from "rad-parser";

const dicomBytes = new Uint8Array(fs.readFileSync("test.dcm"));

// Use { type: 'light' } to skip pixel data value
const dataset = parse(dicomBytes, { type: "light" });

const patientName = dataset.string("x00100010"); // Patient's Name
const studyDate = dataset.string("x00080020"); // Study Date

console.log(`Patient: ${patientName}, Study Date: ${studyDate}`);
```

### **Example 2: Automatic Image Decoding**

Use the `parseAndDecode()` helper to automatically parse a file and decompress the pixel data.

```typescript
import * as fs from "fs";
import { parseAndDecode } from "rad-parser";

async function getRawPixels(filePath: string) {
    const dicomBytes = new Uint8Array(fs.readFileSync(filePath));

    // This function parses the file AND decodes the pixel data
    const dataset = await parseAndDecode(dicomBytes);

    const pixelDataElement = dataset.elements["x7fe00010"];
    const rawPixelData = pixelDataElement.Value as Uint8Array;

    console.log(`Decoded pixel data size: ${rawPixelData.length} bytes`);
    return rawPixelData;
}
```

### **Example 3: Streaming (Node.js)**

```typescript
import * as fs from "fs";
import { StreamingParser } from "rad-parser";

const parser = new StreamingParser({
    onElement: el => {
        // el.dict contains the parsed element(s) for this chunk
    },
    onError: err => console.error("Streaming error:", err),
    maxBufferSize: 50 * 1024 * 1024, // optional
    maxIterations: 500, // optional
});

const readStream = fs.createReadStream("large.dcm");
readStream.on("data", chunk => parser.processChunk(new Uint8Array(chunk)));
readStream.on("end", () => parser.finalize());
```

### **Example 4: Manual Codec Integration (Advanced)**

For custom decoders (e.g., a proprietary compression format or a specific WASM library), you can register a configured codec.

```typescript
import { registry, Jpeg2000Decoder, parseAndDecode } from "rad-parser";
import myCustomJ2kDecoder from "./my-custom-j2k-decoder";

// 1. Instantiate the adapter with your external decode function
const customCodec = new Jpeg2000Decoder(myCustomJ2kDecoder);

// 2. Register it with a high priority
registry.register(customCodec);

// 3. Now, parseAndDecode will use your custom codec for JPEG 2000 files
// const dataset = await parseAndDecode(dicomBytes);
```

## Building from Source

To build the project and its WASM dependencies from source, you need [Zig](https://ziglang.org/) (tested with 0.13.0) installed.

1. **Clone the repository with submodules:**

    ```bash
    git clone --recursive https://github.com/rad-medica/rad-parser.git
    cd rad-parser
    ```

    If you already cloned it without submodules, initialize them:

    ```bash
    git submodule update --init --recursive
    ```

2. **Install dependencies with Bun:**

    ```bash
    bun install
    ```

3. **Build the WASM modules (Rust):**

    ```bash
    rustup target add wasm32-unknown-unknown
    cargo generate-lockfile
    cargo install wasm-bindgen-cli --version "$(cargo pkgid wasm-bindgen | sed 's/.*[@#]//')"
    bun run build:wasm
    ```

    The output goes to `dist/package/rad-*`. The test suite needs it (the WASM
    tests fail early with these instructions when it is missing).

4. **Build the TypeScript project:**

    ```bash
    bun run build
    ```

### Testing

```bash
bun run build:wasm   # once, see above
bun run test
```

Tests use small synthetic files committed in `tests/fixtures/synthetic`
(no patient data, see `tests/fixtures/README.md`). Set
`RAD_PARSER_TEST_DATA=<dir>` to run the file-based tests on more data.

`tests/integration/synthetic_evaluator.test.ts` compares rad-parser with
dicom-parser (selected top-level and nested attributes, Pixel Data bytes) and
checks parse → write → parse on a directory of files generated with
[radspider](https://github.com/rad-medica/radspider):

```bash
cargo run --release -p radspider-synth -- <dir>/synth
cargo run --release --example synth_ct -- <dir>/ct 128 40
cargo run --release --example synth_documents -- <dir>/objects 128 40
RAD_PARSER_SYNTH_DIR=<dir> bun run vitest run tests/integration/synthetic_evaluator.test.ts
```

It is skipped when `RAD_PARSER_SYNTH_DIR` is not set.
